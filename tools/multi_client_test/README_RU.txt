RD6006P: проверка нескольких Modbus TCP-клиентов и веб
Версия скрипта 1.0. Python 3.9 или новее, только стандартная библиотека.
Ничего устанавливать через pip не нужно. Прошивку менять не требуется.

В прошивке taxom.8 и новее подробная диагностика по умолчанию выключена.
Для полного отчета о UART включите Configure -> Enable detailed diagnostics
и нажмите Save перед запуском. После проверки галочку можно снять.
С выключенной диагностикой сам тест работает, но подробные поля uart/timing
не пополняются. Основные счетчики запросов, ошибок и повторов работают всегда.

БЫСТРЫЙ ЗАПУСК НА WINDOWS

1. Распакуйте весь ZIP в обычную папку.
2. Закройте оба TestController. Home Assistant можно оставить для чтения.
   На время теста отключите автоматизации, управляющие этим БП.
3. Подключенная нагрузка должна допускать многократное включение/выключение:
   скрипт действительно переключает физический выход с ТЕКУЩИМИ уставками.
4. Запустите START_TEST.cmd двойным щелчком.

Готовые настройки:
  Адрес:                  192.168.1.176
  Modbus TCP:             502, unit 1
  HTTP:                   80
  Продолжительность:      10 минут
  Читающие TCP-клиенты:   2 независимых постоянных соединения
  Управляющий клиент:     еще 1 TCP-соединение
  Цикл каждого читателя:  не чаще раза в секунду, без попыток догнать график
  Запросы читателей:      11 групп как в ТК + состояние выхода (регистр 18)
  Веб:                    GET /status раз в секунду; /control/ раз в 30 секунд
  Диагностика:            до/после теста и примерно раз в 30 секунд
  Выход ON/OFF:           примерно каждые 10 секунд

КАК ПРОВЕРЯЕТСЯ УПРАВЛЕНИЕ

По умолчанию команды чередуются: Modbus, веб, веб, Modbus, затем повтор.
Поэтому оба способа проверяются на включение И выключение. Через Modbus
записывается только регистр 18. Веб-команда совпадает с кнопкой ON/OFF:
GET /toggle_out. Уставки напряжения/тока, пресеты, защиты и калибровки
скрипт никогда не записывает.

Для каждого переключения проверяются:
  - правильность Modbus transaction ID, unit, функции, длины и эха записи;
  - подтверждение состояния отдельным чтением регистра 18;
  - получение нового состояния обоими читающими клиентами и /status;
  - сохранность исходных уставок напряжения и тока;
  - задержка команды и задержка появления состояния у каждого наблюдателя.

Запросы, начатые до переключения или во время перехода, не считаются
устаревшими ответами. После подтверждения дается 0,5 секунды на переход.
Каждый наблюдатель должен подтвердить состояние свежим запросом.
Число 0 в измерениях само по себе НЕ считается ошибкой, особенно при OFF.
Физическое напряжение на клеммах без внешнего измерителя не проверяется.

Неудавшаяся запись и /toggle_out не отправляются автоматически повторно.
Если ACK потерян, скрипт проверяет результат чтением, сохраняя ошибку ACK
в отчете. Неподтвержденная команда, неожиданное состояние выхода или
изменение уставок останавливают дальнейшие переключения.

ОСТАНОВКА И РЕЗУЛЬТАТЫ

Ctrl+C останавливает тест. При штатном завершении и Ctrl+C скрипт пытается
восстановить И ПОДТВЕРДИТЬ исходное состояние выхода. Если это не удалось,
появится RESTORE FAILED: проверьте состояние на самом БП. Принудительное
завершение процесса, закрытие окна или потеря питания не позволяют
гарантировать выполнение процедуры восстановления.

В папке results создается отдельная папка прогона и ZIP рядом с ней.
Пришлите итоговый ZIP. Он содержит:
  summary.json             общий результат, ошибки и задержки
  operations.csv           все операции и сырые значения регистров
  events.jsonl             переключения, наблюдения и снимки диагностики
  diagnostics_before.json  диагностика до нагрузки
  diagnostics_after.json   диагностика после восстановления выхода
  run_config.json          параметры запуска

PASS означает отсутствие зарегистрированных ошибок и подтвержденное
восстановление выхода. FAIL требует просмотра журнала: даже единичная
ошибка HTTP, Modbus или проверки будет сохранена. INTERRUPTED означает
остановку Ctrl+C без ошибок. Успешные ответы не показывают повторы UART
внутри ESP: они отдельно видны в diagnostics_delta итогового отчета.

ЧИСЛО СОЕДИНЕНИЙ

В прошивке максимум 4 Modbus TCP-соединения. По умолчанию тест занимает 3,
оставляя одно для HA. Оба ТК на время теста закройте. Веб не занимает
Modbus TCP-слоты. При --readers 3 тест займет все 4 слота: для такого
прогона отключите также Modbus-интеграцию HA.

ДРУГИЕ ПАРАМЕТРЫ (PowerShell в папке со скриптом)

Только Modbus-команды, веб продолжает читать и загружать страницу:
  py -3 .\rd6006_multi_client_test.py --control-mode modbus

Только веб-команды, Modbus-клиенты продолжают читать:
  py -3 .\rd6006_multi_client_test.py --control-mode web

Без веб-нагрузки, только Modbus:
  py -3 .\rd6006_multi_client_test.py --no-web

20 минут, 3 читателя + управляющий (закрыть ТК и отключить Modbus HA):
  py -3 .\rd6006_multi_client_test.py --duration 1200 --readers 3

Другой IP:
  py -3 .\rd6006_multi_client_test.py --host 192.168.1.176

Все параметры:
  py -3 .\rd6006_multi_client_test.py --help

Скрипт обращается только к указанному БП; внешних сервисов и телеметрии нет.
Пакет проверен на локальном имитаторе Modbus/HTTP. Реальный БП тестируется
только после запуска на вашем ПК.
