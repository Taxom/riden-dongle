# Riden RD6006P для Home Assistant — 0.1.2

Локальная интеграция Modbus TCP и карточка по выбранному образцу: плитки слева, график напряжения и тока с разными шкалами справа. На узком экране график переходит под плитки. Карточка не требует Mushroom, ApexCharts, card-mod, MQTT или HACS.

Пакет предназначен для **RD6006P, код модели 60065**, и Wi-Fi-моста `Taxom/riden-dongle`. Обновление HA исправляет батарейный канал независимо от версии Wi-Fi-модуля; прошивка `1.7.0-taxom.11` отдельно исправляет то же показание в веб-интерфейсе модуля.

Для предварительного просмотра распакуй архив и открой `demo.html` в браузере. Это демонстрация с вымышленными показаниями, без подключения к БП. Иконки в рабочем HA предоставляет его интерфейс.

Проверено программно на Home Assistant Core **2026.11.1**. Интеграция 0.1.2 проверена программно; аппаратные проверки прошивки Wi-Fi-модуля не заменяют проверку интеграции на конкретном устройстве.

## Обновление установленной версии 0.1.0 / 0.1.1

Версия 0.1.2 исправляет масштаб напряжения батареи (регистр 33: 0,01 В) и добавляет в карточку режим зарядки, напряжение батареи, заряд (Ah) и энергию (Wh) за сеанс. Сохраняет исправления мигания карточки и запуска HA при выключенном БП из 0.1.1. Интеграцию удалять и добавлять заново не нужно. Четыре сущности батареи, отключённые старой версией интеграции, включатся автоматически. Сущности, отключённые пользователем вручную, сохранят это состояние.

«Режим зарядки» показывает флаг батарейного режима БП, а CV/CC остаётся отдельным режимом выхода. Ah и Wh — сбрасываемые счётчики БП за сеанс, не полная ёмкость и не процент заряда аккумулятора. Напряжение батареи читается отдельным каналом и может отличаться от выходного напряжения. Используемый регистр Modbus 33 передаёт сотые вольта (делитель 100). Экран UniSoft может показывать тысячные, которые в этом регистре не доступны. Разница показаний выхода и V-BATT не исправляется программным смещением.

Через WinSCP замени папку `custom_components/rd6006p` в `/homeassistant/custom_components/` и файл `www/rd6006p-card.js` в `/homeassistant/www/` содержимым этого архива. В параметрах ресурсов панели **отредактируй существующий ресурс**:

```text
/local/rd6006p-card.js?v=0.1.2
```

Тип остаётся JavaScript module. Затем перезапусти HA Core и обнови браузер через Ctrl+F5. Не добавляй второй ресурс рядом со старым: разные версии одного custom element не должны одновременно загружаться в одной странице.

Пользовательские лимиты, адрес и существующие ID сущностей сохраняются. При старте без питания БП карточка остаётся стабильно недоступной; после его включения данные возвращаются на следующем успешном опросе. Подключение и восстановление не меняют выход и уставки.

## Установка через SSH

1. Скачай артефакт Home Assistant из успешного запуска GitHub Actions **Firmware checks**, извлеки из него `RD6006P_HA_v0.1.2.zip` и скопируй его в каталог конфигурации HA через свой SSH/SFTP-клиент. Обычно это `/config`; в некоторых приложениях HA — `/homeassistant`. Нужен каталог с `configuration.yaml`.
2. В терминале HA выполни, если архив лежит в `/config`:

```sh
cd /config
unzip RD6006P_HA_v0.1.2.zip -d rd6006p_install_v0.1.2
sh rd6006p_install_v0.1.2/install.sh /config
ha core check && ha core restart
```

Для `/homeassistant` замени `/config` в командах на `/homeassistant`. Команды `ha core` рассчитаны на HA OS / Supervisor. Если команды `ha` нет в выбранном SSH-подключении, проверь конфигурацию и перезапусти Home Assistant через его интерфейс.

Установщик копирует только `custom_components/rd6006p` и `www/rd6006p-card.js`. Предыдущую версию этих файлов сохраняет в `rd6006p_backups/<дата-время>`. Не меняет `configuration.yaml`, настройки HA, часы, уставки или состояние БП и сам не перезапускает HA.

3. После перезапуска: **Настройки → Устройства и службы → Добавить интеграцию → Riden RD6006P**. Введи:

| Поле | Значение |
|---|---|
| IP-адрес | `IP-адрес Wi-Fi-модуля БП` |
| Порт | `502` |
| Unit / slave ID | `1` |

Добавление проверяет модель и читает состояние. Серийный номер определяется автоматически; второй экземпляр той же интеграции для этого БП не создаётся.

4. В ресурсах панелей добавь **JavaScript module**:

```text
/local/rd6006p-card.js?v=0.1.2
```

Путь в интерфейсе: **Настройки → Панели мониторинга → меню ⋮ → Ресурсы**. Если пункта нет, включи расширенный режим в профиле пользователя. После добавления ресурса обнови страницу браузера. Если карточка не появилась, обнови без кэша (`Ctrl+F5`). В YAML-режиме панелей добавь этот URL в `lovelace.resources` с `type: module` вместо регистрации через интерфейс.

5. Добавь ручную карточку и вставь содержимое `dashboard_card.yaml`:

```yaml
type: custom:rd6006p-card
title: Riden RD6006P
hours_to_show: 1
language: ru
```

Карточка сама находит сущности этой интеграции, в том числе после их переименования. Если БП несколько, добавь `serial: "<серийный номер>"`. Он виден на странице устройства HA. Также есть простой визуальный редактор названия, номера и периода истории.

Для широкого вида, как на образце, используй отдельный вид панели типа **Panel / одна карточка**. Готовый вариант одного вида находится в `dashboard_view.yaml`; добавь его в массив `views` своей панели. В узком разделе карточка автоматически станет вертикальной.

## Управление

- **ON** и **OFF** вызывают разные абсолютные действия. Видимое состояние меняется только после чтения БП. Пока операция идёт, кнопки блокируются.
- Введи напряжение/ток или используй `−`/`+`, затем нажми **Применить** или Enter. Редактирование поля и кнопки `−`/`+` меняют только черновик. Escape отменяет черновик.
- Шаг аппаратной уставки: **0,001 В / 0,0001 А**. Для удобства `−`/`+` по умолчанию меняют черновик на 0,1 В / 0,001 А. Эти шаги карточки можно изменить через `voltage_step` и `current_step`.
- Над полем показана последняя фактически прочитанная уставка. Она обновляется при изменениях с панели БП, из TestController и веба. Если в поле уже есть черновик, внешнее изменение обновляет показание над ним и не перетирает ввод.
- Начальные пределы записи HA — **3,000 В / 0,1000 А**. Их можно изменить в параметрах интеграции до программных пределов модели **60,1 В / 6 А**. Сохранение параметров не меняет действующие уставки и не записывает аппаратные OVP/OCP.
- Перед ON отдельно читаются текущие V/I. Если они превышают пределы HA, команда ON не отправляется. OFF доступен независимо от этих пределов. Другой клиент всё ещё может изменить БП после проверки: это не аппаратная защита и не межклиентская блокировка.

Если текущая уставка, изменённая другим клиентом, выше лимита HA, отображается её реальное значение. Интеграция не понижает его автоматически. Чтобы редактировать такую уставку из HA, измени пользовательский предел либо введи меньшее значение.

## Сущности

Все сущности принадлежат одному устройству. ID зависят от языка HA и возможного переименования, поэтому карточка не использует жёстко заданные ID.

| Сущность | Тип | Обновление / особенности |
|---|---|---|
| Выход | switch | Абсолютная FC6 в 18, затем FC3 |
| Уставка напряжения | number | 0,001 В, FC6 в 8 + чтение |
| Предел тока | number | 0,0001 А, FC6 в 9 + чтение |
| Выходные V / A / W | sensor | Общий основной опрос |
| Входное напряжение | sensor | 0,01 В |
| Режим выхода | enum sensor | CV / CC / неизвестно |
| Защита | enum sensor | Норма / OVP / OCP / неизвестно; есть raw |
| Внутренняя температура | sensor | Медленный опрос |
| Связь | binary_sensor | ON после успешного основного чтения, OFF после ошибки |
| Клавиатура заблокирована | binary_sensor | Только чтение |
| Напряжение батареи | sensor | Включена; шаг 0,01 В |
| Внешняя температура | sensor | Отключена в реестре; дополнительно требует флаг подключённого датчика |
| Заряд / энергия за сеанс | sensor | Включены; сбрасываемые счётчики без `total_increasing` |
| Режим зарядки | sensor | Включён / выключен; только чтение |
| Пресет | sensor | Отключён в реестре; только чтение |

Дополнительные сущности включаются на странице устройства HA. При выключенном флаге внешнего датчика температура остаётся `unknown`. При включённом флаге подавляется наблюдавшееся служебное значение **−89 °C**; достоверного регистра присутствия датчика в исходном протоколе не обнаружено. Другие отрицательные температуры не отбрасываются. Если твой отключённый датчик выдаёт иной код, оставь флаг выключенным и сообщи сырое значение из локальной диагностики.

## Частота, связь и история

- Основной блок **8–20**: один FC3 раз в **2 с**.
- Медленные блоки **0–5** и **32–41**: по одному FC3 раз в **20 с**.
- Тайм-аут ответа: **5 с**, настраивается в пределах 2–15 с. Опросы не перекрываются и не накапливаются.
- Один клиент интеграции использует один постоянный TCP-сокет. Управление проходит перед ожидающими запросами телеметрии, но уже начатый запрос нельзя прервать. Во время переподключения отдельно проверяется модель и серийный номер.
- После ошибки основного чтения измерения и управление становятся недоступными. Последние значения сохраняются внутри как последние известные. Успешный следующий опрос восстанавливает доступность без записей.
- Ошибка медленного блока делает недоступными только его сущности. Основная телеметрия остаётся доступной, если её чтение успешно.
- Потерянный ACK записи не вызывает повтор FC6. Интеграция закрывает сомнительное соединение и отдельно читает состояние. Совпадение подтверждает текущее состояние, а не исключительное авторство HA. Если чтение не получилось, результат неизвестен; если получилось другое значение, оно отображается, а действие возвращает ошибку.
- Перезапуск HA, перезагрузка интеграции и восстановление сети не записывают прежний выход или уставки. Не используется восстановление `RestoreEntity` для управления БП.

График берёт историю **из HA Recorder/History**, не из ESP. Доступны 15 минут, 1, 6 и 24 часа. История обновляется раз в минуту; числовые показания — с частотой основного опроса. Линии ступенчатые, потому что Recorder хранит изменения состояния; `unavailable` создаёт разрыв. Оси подбираются отдельно по записанным V/A; шкалы под плитками показывают пределы записи HA.

Если график пуст, дождись первых измерений и проверь, что `sensor` напряжения и тока не исключены из Recorder и что включена интеграция History. Старые данные до добавления интеграции отсутствуют. Подробные трассы ESP автоматически не включаются; HTTP-статус ESP не опрашивается.

Внизу карточки есть ссылки на `/control/` и JSON `/diagnostics/modbus`. Это ссылки, а не фоновый опрос. Встроенная кнопка «Скачать диагностику» интеграции HA выгружает уже имеющиеся данные и счётчики клиента, без дополнительного UART/HTTP-обмена; адрес и серийный номер из выгрузки исключены.

## Короткая проверка после установки

1. Подключи интеграцию и проверь соответствие V/I, выхода, CV/CC и защиты экрану БП. Само подключение не должно ничего изменить.
2. Измени уставку с передней панели или ТК: HA должен увидеть её на ближайшем успешном опросе.
3. Для первого управления оставь выход OFF, сними внешнюю нагрузку и используй согласованные небольшие значения около **2,6 В / 0,05 А**. После проверки чтения примени одну уставку через карточку и сравни экран БП и ТК. Никакой переключающий тест не запускается установкой или открытием карточки.
4. Когда будешь готов проверить выход, отдельно нажми ON, затем OFF; сравни все клиенты. При рабочем параллельном тесте открой два ТК и веб, оставив место для одного постоянного сокета HA: всего мост допускает четыре занятых Modbus TCP-сокета.
5. Оборви Wi-Fi БП и восстанови его. HA должен показать недоступность, затем реальные значения. Самостоятельных записей при восстановлении быть не должно.
6. Перезагрузи интеграцию/HA при заранее известном состоянии и убедись, что оно не изменилось. Окончательную совместимость с двумя ТК и вебом нужно подтвердить именно на оборудовании.

Не пытайся специально терять ACK на подключённой нагрузке: этот сценарий проверен на симуляторе. Проверка тока и стабилизации под нагрузкой в этот пакет не входит.

## Если что-то не добавляется

- «Интеграция не найдена»: проверь `/config/custom_components/rd6006p/manifest.json`, затем перезапусти **Core**, не только обнови браузер.
- «Cannot connect»: доступен ли БП из сети HA, верен ли порт 502 и unit 1, есть ли свободный сокет. Для пробы можно закрыть лишние ТК. Интеграция не включает Modbus в настройках ESP автоматически.
- «Custom element doesn't exist»: проверь ресурс `/local/rd6006p-card.js?v=0.1.2`, тип module и кэш браузера.
- Изменился адрес БП: меню интеграции → перенастроить. Принимается тот же серийный номер; новый БП добавляется отдельно.
- Сообщение о неподтверждённой записи: сначала прочитай фактическое состояние, прежде чем вручную повторять действие.

Для диагностики пришли версию HA Core, точный текст ошибки и диагностику этой интеграции. Токены и пароль Wi-Fi не нужны.
