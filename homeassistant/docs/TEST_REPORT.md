# Проверки RD6006P HA 0.1.2

Дата: 2026-11-24, America/Toronto.

## Результат

- **67 Python-проверок — PASS** на Home Assistant Core 2026.11.1 / CPython 3.14.10.
- **Проверки DOM карточки — PASS** в Node.js / jsdom 31.0.0.
- Ruff, компиляция Python, синтаксис JavaScript и shell — PASS.
- Установка и повторная установка с резервной копией проверены во временном каталоге; исходный `configuration.yaml` не изменился.

Предупреждение тестового запуска относится к наследованию `aiohttp.web.Application` в HTTP-компоненте самого HA, а не к этой интеграции.

## Батарейный канал и обновление 0.1.2

Регистр 33 проверен на сырых значениях 0, 1, 417, 6010 и 65535: используется делитель 100 независимо от делителя выходного напряжения. Отдельно проверена пара 4,17 В батареи / 4,148 В выхода. Реальные сущности HA публикуют режим on/off и заряд/энергию за сеанс, сохраняют настоящий ноль и сброс счётчиков. Ошибка батарейного блока делает недоступными только соответствующие сущности.

Обновление включает сущности с disabled_by=integration, сохраняет disabled_by=user и пользовательские лимиты. В тестах батареи все запросы — чтение FC3, без FC6. В DOM проверены новые плитки, Ah/Wh, преобразования mAh/kWh, выключенный режим и недоступность.

## Регрессия запуска с выключенным БП (из 0.1.1)

В 0.1.0 воспроизведено точное мигание из сообщения пользователя: при `hass.states = {}` каждый вызов setter `hass` попеременно добавляет/удаляет `online` у индикатора и `active` у обеих кнопок, хотя обе кнопки недоступны и подпись говорит об отсутствии данных. Причина: `VALID(undefined)` возвращал `undefined`, а `classList.toggle(name, undefined)` работает как переключение, а не как явное удаление класса. Новый DOM-тест падал на старой карточке и проходит на исправленной.

Добавлены реальные тесты HA: запуск при отказе TCP-соединения, последующее появление БП с автоматическим опросом; перезагрузка интеграции при недоступном Modbus; первоначальный чужой serial и восстановление после появления правильного. Во всех сценариях проверяется отсутствие FC6, сохранение сущностей и пользовательских лимитов. Отсутствие первого ответа больше не переводит существующую запись интеграции в отложенную установку.

Карточка сохраняет ID выбранного БП при временном исчезновении метаданных. Пустые, восстановленные и неизвестные состояния не включают подсветку и не разрешают управление. После регистрации всех платформ интеграция повторно публикует полную карту ID: первоначальное состояние датчика связи могло появиться раньше регистрации остальных сущностей.

## Границы проверки

**Подключения к реальному RD6006P не выполнялись.** Симулятор слушает только `127.0.0.1`, serial 3111; он не воспроизводит электрическую часть БП, UART-помехи ESP, все особенности UniSoft или ограничения реальной Wi-Fi-сети.

Полный визуальный тест в браузере и автоматическая проверка мобильной раскладки здесь **не завершены**: локальная среда не предоставила работающий путь к браузерному предпросмотру. Проверена логика и структура DOM; реальный рендеринг, темы, иконки и размеры следует проверить после установки. Для повторения подготовлен `tests/test_card.cjs` (Playwright), но его нельзя считать пройденным в этом запуске. В `demo.html` находятся только вымышленные данные.

Нужно отдельно подтвердить совместную работу **HA + два TestController + веб** на твоём оборудовании. Многосуточный прогон, стабилизация тока под нагрузкой и точность измерений не проверялись. Интервалы 2/20 с — выбранные настройки интеграции, не установленный нижний предел UniSoft.

## Повторение программных проверок

В отдельном Python-окружении с подходящей версией Python:

```sh
pip install homeassistant==2026.11.1 pytest pytest-asyncio ruff
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 pytest -p pytest_asyncio.plugin tests
ruff check .
python -m compileall -q custom_components
```

В отдельном каталоге Node или в распакованном проекте:

```sh
npm install --no-save jsdom@31.0.0 playwright@1.62.1
node tests/test_card_dom.cjs
node tests/test_card_recovery.cjs
node --check www/rd6006p-card.js
```

Для визуального теста в среде с браузером Playwright:

```sh
npx playwright install chromium
node tests/test_card.cjs
```

Тесты и dev-зависимости не устанавливаются в HA установщиком. В `manifest.json` список runtime-зависимостей интеграции пуст.
